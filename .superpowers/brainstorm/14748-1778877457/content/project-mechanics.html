How a "Project" works — law firm example

The law firm is your tenant. They have one or many Projects. Here's the full flow.

Step 1 — CISO creates a Project

Admin UI → Projects → New Project
Project name: Zuckerberg Employment Contract
Description: M&A matter for Meta executive employment dispute
Sensitive keywords: Zuckerberg Marc Z employment contract executive compensation Project Zeus
Applies to: M&A Team, Corporate Law Division

Step 2 — CISO writes a rule for this project

Policy rule attached to "Zuckerberg Employment Contract"
IF message contains any keyword from Zuckerberg Employment Contract
AND destination is any AI chat site (ChatGPT, Claude, Gemini...)
THEN → BLOCK
Message shown to employee: "This message contains confidential matter content and cannot be sent."

Step 3 — Lawyer types a message in ChatGPT

ChatGPT — lawyer's browser
You:
Can you help me draft a clause about executive compensation for a senior tech executive? The package involves...

Step 4 — Extension detects it

BLOCKED

Extension matched "executive compensation" → Project: Zuckerberg Employment Contract → Rule: Block on AI sites

If it were WARN instead:

Overlay pops up: "This may contain confidential matter content. Are you sure you want to send?" → user can proceed or cancel.

So what does the CISO actually "add to the policy"?

Three things: (1) a Project with a list of sensitive keywords, (2) which teams/divisions it applies to, and (3) what to do when those keywords appear in a message to a given destination — warn or block.

The policy compiler (already exists in the backend) takes all projects + rules and builds the final ruleset that gets pushed to the extension.
