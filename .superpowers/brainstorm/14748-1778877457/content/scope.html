What You're Building — System Scope

This is a large product. Let's agree on the sub-projects before designing any one piece.

Five Independent Subsystems

1

Org Structure

Companies → Divisions → Teams → Users. Replace the current "matters" model with a generic multi-level org hierarchy. This is the foundation everything else sits on.

2

Policy Engine

Policy rules scoped to org units. Website / domain groups. Actions: warn or block. Custom confidential terms per matter/case. JSON schema that can represent all of this.

3

Admin Web App

Side-panel layout for CISOs and chosen admins. JSON editor + AI chat interface (Loveable-style) that edits policy behind the scenes. Domain preview panel. Policy tester.

4

Chrome Extension

Employee-facing. Signs in, downloads org policy, enforces rules based on user's team membership. Warn or block before sending to AI sites.

5

AI Policy Assistant

Chat UI that talks to Claude (or GPT) and translates natural language into policy JSON changes. Shows progress as it edits. The "Loveable for policies" interface.

Recommended build order

1 → 2 → 4 → 3 → 5  |  Org structure first (everything depends on it), then policy schema, then extension enforcement, then admin UI, finally AI assistant
