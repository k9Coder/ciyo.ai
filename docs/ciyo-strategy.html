03 · Foundation

What You've Actually Built

One sentence: Pretzel is an AI-era Data Loss Prevention tool — a browser extension that intercepts employee prompts before they hit ChatGPT/Claude/Gemini, runs them through a configurable policy engine, and warns or blocks sensitive data. The Console lets security teams manage everything without touching code.

🧩
Browser Extension
Intercepts prompts in real-time. Syncs policy on every browser open. Warns or blocks based on rules. Works on any AI site you configure via CSS selectors — not just the big three.
⚙️
Policy Engine
Four detection types: keyword matching, regex patterns, entropy (API keys / tokens), composite risk scoring. Versioned, published snapshots — rollback-safe.
🏢
Pretzel Console
Multi-tenant. Full org hierarchy. Analytics + audit log. Clerk auth. Stripe + PayPal billing wired. AI assistant. Policy publish flow. Everything a security admin needs in one place.
🤖
AI Policy Assistant
"Block SSNs on the Finance team." The assistant proposes structured actions and waits for human approval. Currently under-powered — the AI section below is a full overhaul plan.
📊
Analytics Pipeline
Events table captures every warn/block with member, site, matched term, timestamp. Scans table tracks volume per user. Foundation for dashboards, compliance reports, exec briefings.
💳
Billing Infrastructure
Stripe + PayPal integrated, subscription status in DB, tenant activation live. You can take money today. Missing: usage-limit enforcement on free tier.

06 · Payment Stack

How to Take Money

You've wired both Stripe and PayPal. Here's the honest analysis of which to use, which to drop, and what to add later.

✦ Primary — Keep & Double Down
Stripe
The standard for B2B SaaS. Every enterprise buyer pays by credit card or ACH bank transfer — Stripe handles both.
Pros
  • Best developer DX, by far
  • Handles subscriptions, metered billing, annual contracts
  • Stripe Checkout = PCI compliance included
  • ACH bank transfer for large enterprise invoices
  • Customer Portal for self-serve upgrades/downgrades
  • Startup fee deals via accelerators
Cons
  • 2.9% + 30¢ per transaction
  • Manual invoicing for enterprise deals needs extra setup
✗ Remove — Wrong for this market
PayPal
Built for consumer e-commerce and freelancers. B2B security buyers don't use PayPal. It adds complexity and signals "small indie project" to enterprise procurement.
Pros
  • Consumer recognition
  • Some countries prefer it
Cons
  • No B2B buyer uses PayPal for SaaS
  • Signals consumer product
  • Extra integration complexity
  • Worse developer experience
  • Weaker fraud protection
◈ Add Later — For European Expansion
Paddle
Paddle acts as the merchant of record — they handle all VAT, GST, and tax complexity globally. Worth adding when you have European customers.
Pros
  • Handles EU VAT automatically
  • Merchant of record = you don't deal with tax
  • Good for global SaaS expansion
  • Better localised checkout
Cons
  • 3.5% + $0.50 fee (more expensive)
  • Less control over checkout
  • Overkill pre-launch
Decision: Stripe only for launch. Remove PayPal — it's adding code complexity and zero value for a B2B security product. Configure Stripe Billing with monthly + annual plans, a free tier plan (free of charge, but metered), and ACH bank transfer enabled for enterprise. Add Paddle in 12–18 months when European deals start closing.
Stripe Billing
Subscription management, proration, annual plans, metered usage. This is what manages your plan tiers automatically.
Stripe Customer Portal
Self-serve upgrade / downgrade / cancel. Drops into the Console Settings page. Saves you building all that UI yourself.
Stripe Checkout
The actual payment page. Stripe hosts it — zero PCI scope for you. One link from your upgrade prompt = working payment.
ACH Bank Transfer
Enable for Enterprise tier. Large companies pay by bank transfer. This lets you invoice them properly through Stripe rather than manually.

The free tier's job is acquisition, not revenue. Design it so it works perfectly for 1–3 power users, breaks exactly when team use starts, and makes the FOMO real.

Breaks exactly when team use starts

08 · Retention

The Lock-In Stack

These are genuine switching costs, not dark patterns. The longer they use Pretzel, the harder it is to leave — because the product becomes embedded in their security operations.

1
Policy Lock-In
After 6 months they have 200+ rules across dozens of subjects, scoped to specific teams. Migrating to a competitor = weeks of work. Nobody does it voluntarily.
2
Audit Trail Dependency
SOC2, HIPAA, and GDPR auditors ask for historical violation logs. Once Pretzel is the system of record, leaving requires exporting and migrating all compliance history. That's a legal and IT project — not a SaaS cancellation.
3
AI Assistant Habit
"Just ask Pretzel" becomes how admins think about security policy. Switching means starting fresh with a new tool that doesn't understand their org. Cognitive switching cost.
4
Org Hierarchy Embedding
Their divisions, teams, and roles are mirrored in Pretzel. Ripping it out = re-doing all org configuration. IT teams hate that kind of project.
5
Chrome Enterprise Force-Install
Once IT pushes the extension via Chrome Enterprise policy, it's on every managed machine. Removing it requires an active IT rollout. Inertia works entirely in your favour.
6
Integration Web
Every Slack alert, SIEM connector, and API integration adds a thread to the enterprise fabric. Switching means disconnecting security infrastructure — a full CISO review, not a SaaS cancel.
09 · AI Assistant Overhaul

The Assistant Is Barely Started

Right now the assistant does 6 things: create/update/delete rules and subjects. That's a CRUD interface with a chat wrapper. You're running an LLM — it should feel like one. Here's the full vision.

Current State
6 CRUD actions only (create/edit/delete rules + subjects)
No access to analytics or event data
Static org snapshot as context — no querying
No streaming — full response appears at once
Last 20 messages as history (no long-term memory)
No proactive suggestions — purely reactive
No rule testing or policy simulation
PayPal-style generic LLM interface — model swap not tracked
What It Should Be
Full policy management: rules, subjects, bulk operations, undo
Can query events: "What happened last week?" → reads real data
Tool use (Anthropic tool_use) — queries DB, doesn't just guess
Streaming SSE — responses appear word by word
Proactive digest — surfaces insights admins didn't ask for
Policy gap analysis: "Am I HIPAA-ready?"
Prompt simulation: "Would this trigger any rules?"
Claude claude-sonnet-4-6 with prompt caching on the system prompt
New Capabilities to Build
🔍
Analytics Narration Highest impact
Give the assistant a query_events(filters) tool. It can then answer: "How many blocks happened this week in Engineering?" or "Which user triggered the most warnings last month?" — with actual data, not hallucinated answers. This turns the assistant from a config tool into a genuine security intelligence interface.
💡
Proactive Daily Digest Build now
Every morning the assistant surfaces 2–3 things admins should know without asking: "3 users in Engineering triggered entropy rules yesterday — 2 looked like real API keys. Want me to tighten the rule?" This is the feature that makes admins check the Console daily, which is the best retention mechanism you can build.
🧪
Prompt Simulation / Rule Testing Build now
Admin types a hypothetical prompt: "What would happen if an employee sent: 'Here's our Q3 revenue forecast: $4.2M'" — the assistant runs it against all active rules and explains which ones would fire, why, and what the user would see. Invaluable for policy QA and onboarding.
📋
Policy Gap Analysis Build now
"Am I covered for HIPAA?" — the assistant compares current rules against a known checklist of regulated data types (PHI fields, PCI patterns, attorney-client privilege keywords) and produces a gap report: what's covered, what's missing, suggested additions. This becomes a key selling point for compliance-driven buyers.
🗂️
Guided Onboarding Wizard Q3
First-time admin starts a conversation: "Tell me about your company and what data you handle." Assistant asks 4–5 questions (industry, team size, AI tools used, compliance requirements) then generates a starter policy tailored to them. Replaces the "staring at a blank policy page" problem that causes new user churn.
📝
Executive Summary Generation Q3
"Write me a summary for my CISO of what happened with AI usage this month." The assistant reads the events table, generates a professional 1-page summary with key metrics, risk highlights, and recommendations. Admin copy-pastes it into Slack or a PDF. Makes every user look good to their leadership — that's a powerful retention mechanic.
🔄
Smart Rule Deduplication Q3
"Review my rules and tell me if anything overlaps." The assistant scans all rules, identifies semantic duplicates and redundancies, and proposes a cleaner consolidated version. Keeps policy lean and prevents "rule soup" as orgs accumulate hundreds of rules over time.
↩️
Undo / Change History Q4
"Undo the last 3 changes." Each applied action is logged. The assistant can reverse them in order. Essential for admins who fat-finger a bulk operation — builds confidence to use the AI more aggressively when they know they can undo.
Technical Upgrades (The Infrastructure)
Streaming SSE
Replace the current full-response endpoint with a Server-Sent Events stream. The reply appears word by word. Makes the AI feel alive and responsive instead of showing a loading spinner for 3 seconds. Frontend change: ~1 day. Backend: ~half day.
Anthropic Tool Use
Replace the current JSON-return pattern with real Anthropic tool_use. Give the model tools: query_events, list_rules, test_prompt. The model decides when to call them — you don't have to tell it when to look up data vs. when to answer from context.
Prompt Caching
The org snapshot (divisions, teams, subjects, rules) in the system prompt can be 2,000–5,000 tokens. Use Anthropic's prompt caching (cache_control: "ephemeral") on this block. 90% cache hit rate = ~75% cost reduction on assistant calls. Critical once usage scales.
Model: Claude claude-sonnet-4-6
The assistant prompt explicitly says "You are the ciyo Assistant." Lean into it — use Anthropic's Claude claude-sonnet-4-6 as the model. It understands the tool-use pattern natively, handles the JSON action schema well, and the quality gap over cheaper models is very visible in complex policy reasoning.
Rate Limiting by Plan
Free tier: 20 assistant messages/month. Starter: 100/month. Business: unlimited. The assistant is a cost centre — each message costs real money. Gating it to Business plan creates a genuine upgrade incentive and keeps your LLM spend manageable.
Confidence + Explanation
Prompt the model to always explain its reasoning and flag uncertainty: "I'm ~80% confident this regex covers all UK phone number formats — here are 2 edge cases it might miss." This builds admin trust and reduces the fear of applying AI suggestions to production policy.
