## Bug Context

### Bug 1 — Extension never loads policy from server

`GET /v1/policy` responds with:
```json
{ "version": 3, "policy": { "version": 1, "tenantId": "...", "subjects": [...], "siteConfigs": {...} }, "tenantName": "...", "plan": "pro", "expiresAt": null }
```

`sync.ts` does `PolicyDocSchema.safeParse(raw)` — this tries to parse the **outer** object. `PolicyDocSchema` expects `version: literal(1)` but gets `version: 3`. Parse always fails silently; policy is never stored.

Fix: `PolicyDocSchema.safeParse((raw as { policy: unknown }).policy)`

### Bug 2 — Members team-assignment route URL mismatch

Router has `POST /members/:id/teams` (teamId in request body). Test calls `POST /members/:id/teams/:teamId` (teamId in URL). Admin frontend also uses the body form. Fix: keep both — add the URL-param variant alongside the existing body-variant.

### Bug 3 — Clerk webhook test mock targets stale instance

```ts
vi.mocked((Webhook as ReturnType<typeof vi.fn>).mock.results[0]!.value.verify)
  .mockImplementationOnce(...)
```
By the time the 5th test runs, `mock.results[0]` is the Webhook instance from test 1. The handler creates a **new** instance per request — the mock on the old instance has no effect; the handler's `catch` never fires; endpoint returns 500 from an unrelated path. Fix: mock the **constructor** for one call so the next `new Webhook()` returns a throwing `verify`.

  it('returns 400 when Svix signature is invalid', async () => {
    const { Webhook } = await import('svix')
    vi.mocked((Webhook as ReturnType<typeof vi.fn>).mock.results[0]!.value.verify).mockImplementationOnce(() => {

Replace with:
```ts
  it('returns 400 when Svix signature is invalid', async () => {
    const { Webhook } = await import('svix')
    ;(Webhook as ReturnType<typeof vi.fn>).mockImplementationOnce(() => ({
      verify: () => { throw new Error('Invalid signature') },
    }))
    const res = await makeWebhookRequest({ type: 'organization.created', data: {} })
    expect(res.status).toBe(400)
  })
```

The key change: instead of reaching into `mock.results[0]!.value.verify` (the first-ever Webhook instance), we call `mockImplementationOnce` on the **constructor** itself so that the **next** `new Webhook(secret)` in the route handler returns an object with a throwing `verify`.

- Clerk app has a webhook pointing to your backend's `/webhooks/clerk` URL
- Backend running: `cd backend && npm run dev`
- Extension loaded unpacked from `dist/` in `chrome://extensions`

**Checklist:**
1. Open a ChatGPT, Claude, or Gemini tab — extension icon should appear active
2. Open the extension popup — should show "Sign in via Settings" (not signed in yet)
3. Click "Sign in via Settings" → opens options page
4. On Account tab → sign in with Clerk — should show your name and email after sign in
5. Close and re-open popup — should show signed-in view with site toggle
6. In the admin console (`cd admin && npm run dev`) — sign in with an admin token, create a subject with a keyword rule (e.g. keyword: "classified")
7. Publish the policy (Publish page → "Publish now")
8. Back in the extension popup → "Sync Now" or wait for auto-sync
9. Type the keyword "classified" into ChatGPT's prompt box and press Send — extension should intercept and show warning modal
10. Admin console → Org Structure → create division, team, add member (the signed-in Clerk user's email)
11. Re-publish policy → re-sync extension → verify same keyword still triggers

**Pass criteria:** Steps 9 and 11 both show the warning modal. No console errors in the background service worker.
